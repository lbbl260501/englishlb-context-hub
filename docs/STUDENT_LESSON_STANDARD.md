# 面向学习者的讲义与项目数据：严格分离规范

## 两种完全不同的文件

**学生讲义（lesson）**是一份可以脱离 GitHub、独立阅读和做题的教材。正文只包括必要的学习目标、真题阅读指引、背景、词汇与词块讲解、句法、篇章分析、练习、答案解析及答案之后的英中双语附录。避免“项目状态、数据校验、仓库操作、覆盖率、提交记录、工作报告、词汇ID、来源核验日志”等内容出现在讲义中。

**项目资料（editorial/data）**用于为上述讲义提供可靠依据，包含真题年份/段落/选项的核验、材料类型、题源链接、词条去重、来源证据、数据表、QA、版本与提交记录。它可以结构化存放，但不能直接编译进学生版。

- 学生可编辑文本及成品：`lessons/<lesson>/student/`。
- 原创练习/中译及释义的结构化教学内容：`lessons/<lesson>/editorial/`；维护脚本从这里生成学生版。
- 原卷/第三方转录/原媒体与词典的核验记录：`lessons/<lesson>/editorial/SOURCE_AUDIT.md`（历史文件迁移前可保留旧路径）。
- 全局课程管理数据：`data/*.json`，不导出到PDF正文。

## 从学习者出发检查“是否像一册教材”

不能仅有“词语—中文释义—例句”列表。每个单元要回答真实读者的问题：为何学习这篇材料？第一遍读哪几个地方？哪种误读容易发生？如何把词语带回句子和篇章？能否在不熟悉的新材料上独立完成任务？

每一册至少完成以下教学链路：

1. **进入文章**：简洁背景、预读问题，阅读任务与题目入口；不先替学生回答。
2. **段落精读**：突出文章的事实、解释、态度与结论的衔接，展示重要限定、证据与选项改写。
3. **词汇与词块**：语境义、必要搭配、对比义项、多个原创例句，必要时讨论词性/结构。复习词不伪装首次引入。
4. **句法训练**：讲解有阅读困难的真实结构与语义边界，而非列语法名词。
5. **自主练习**：与本册语料有关、但不是直接复述的自编短文与题目，包括一部分跨情境迁移。
6. **答案详解**：不是只列答案字母，应交代为何正确、干扰项具体改变了什么范围、对象、时间或程度。
7. **完整英中对照附录**：原创英文例句、阅读原文、题干与选项、练习句子及答案对应的中文翻译集中放在答案之后。

上面是质量门槛，不是刻板页数或题目配额；需要时增加内容，但不为了凑页数重复讲解。

## 来源边界

- **真题**：注明年份、英语（一）、Text及题号；链接可以阅读的试卷，不把第三方解析当官方答案。
- **题源媒体**：只作原刊背景，媒体原文与试卷删节版不是同一件事。
- **第三方转录**：明确标示，独立核对选项、拼写与段落差异。
- **原创内容**：题干、选项、文章与例句清楚标识自编；不得冒充真题。
- 尊重版权：公开讲义不粘贴长篇试卷或媒体全文，使用必要的简短引用和链接即可。

## 编写和出版是两件事

一个候选词出现在草稿、教学脚本或 PDF 中，不等于学生已学会。没有正式发布和主讲核验时，不改变 primary_words / primary exposure；旧样章中已经主讲的词作为 review 或有证据的 sense_extension。

发布前检查：答案与中译准确、PDF逐页渲染正常、教材不混入技术报告、编辑源文件可用、正式文件确实保存在仓库，并运行已有 audit / plan_next / build_snapshot 后记录真实 commit。
